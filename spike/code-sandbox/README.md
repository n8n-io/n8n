# Spike: Code node on the sandbox service

Spec: `SPIKE-SPEC-opus.md`. Results: `SPIKE-RESULTS-opus.md` (both in the parent
folder of this repository). This folder has the workloads and the scripts.
The code is throwaway spike code.

## Parts

| Part | Location |
|---|---|
| n8n backend (flag `N8N_CODE_EXECUTION_BACKEND=sandbox`) | `packages/cli/src/modules/code-sandbox/` |
| Backend selection | `packages/cli/src/workflow-execute-additional-data.ts` (`startRunnerTask`, `getRunnerStatus`) |
| JS runtime (worker) | `packages/@n8n/code-runtime/` |
| Code sandbox image | `docker/images/code-sandbox/` |
| Workloads | `spike/code-sandbox/workloads/` (generated by `scripts/generate-workloads.mjs`) |
| Scripts | `spike/code-sandbox/scripts/` |

The sandbox service part (Task API, code daemon, SDK client, k6 benchmark) is
in the `spike/code-task-api-opus` branch of `n8n-sandbox-service`.

## Run it locally

1. Start the sandbox service with code sandboxes. In `n8n-sandbox-service`:

   ```sh
   CODE_SANDBOX_IMAGE=registry:5000/n8n-code-sandbox:latest make up -d
   ```

2. Build n8n and the code sandbox image, and push the image to the local registry:

   ```sh
   pnpm build --filter=n8n...
   SANDBOX_SERVICE_DIR=../n8n-sandbox-service-opus docker/images/code-sandbox/build.sh n8n-code-sandbox:local
   docker tag n8n-code-sandbox:local localhost:5050/n8n-code-sandbox:latest
   docker push localhost:5050/n8n-code-sandbox:latest
   ```

   The runner pulls the image only if it does not have the tag. After a new push,
   run `docker exec <runner> docker pull registry:5000/n8n-code-sandbox:latest`.

3. Prepare n8n (SQLite in `/tmp/n8n-spike/user`, W5 files, active workflows):

   ```sh
   spike/code-sandbox/scripts/setup.sh
   ```

4. Start the echo server and n8n:

   ```sh
   node spike/code-sandbox/scripts/echo-server.mjs &
   BACKEND=sandbox SCOPE=execution spike/code-sandbox/scripts/start-n8n.sh
   ```

   `start-n8n.sh` sets the spike variables. See the table below.

## Run it on a remote VM

`remote/remote.sh` runs the passes on a Linux VM (Ubuntu, Docker installed, the
user in the `docker` group). The laptop only copies the code and fetches the
results, so its load does not change the numbers.

```sh
export REMOTE=user@host SSH_KEY=~/.ssh/key.pem   # SSH_KEY is optional
R=spike/code-sandbox/remote/remote.sh
$R sync                                 # copy both repositories (no node_modules, dist, .git)
$R setup                                # Node.js, pnpm, k6, n8n build, images, stack, workflows
$R run run5 pool-pass.sh                # results in ~/n8n-spike/run5 on the VM
$R status run5
$R fetch run5                           # to /tmp/n8n-spike/remote/run5
```

- `setup` runs `remote/setup-vm.sh` on the VM. It is safe to run again. Run one step with `$R setup <tools|n8n|service|image|stack|spike>`.
- The sandbox API listens on host port 18080 on the VM (`SANDBOX_API_PORT`), because another service can hold 8080. `~/spike/env.sh` on the VM sets the paths and the API address for the passes.
- The runners run in privileged mode. Use `RUNNER_RUNTIME=sysbox` on a VM with Sysbox.
- Do not run `sync` while a pass runs: bash reads a script while it runs it.
- Each pass writes `host.txt` (CPU, memory, versions) and `load-avg.txt` (load average every 30 s) to its result folder.

|---|---|

## Configuration

| Env | Default | Purpose |
|---|---|---|
| `N8N_CODE_EXECUTION_BACKEND` | `task-runners` | `sandbox` runs JavaScript Code tasks in code sandboxes. Python keeps task runners. |
| `N8N_CODE_SANDBOX_SCOPE` | `execution` | `node`, `execution` or `workflow` |
| `N8N_CODE_SANDBOX_IDLE_TIMEOUT_MS` | `30000` | Release an idle sandbox |
| `N8N_CODE_SANDBOX_MAX_LIFETIME_MS` | `60000` | `workflow` scope: drain a sandbox after this time |
| `N8N_CODE_SANDBOX_SLOTS` | `1` / `2` / `4` | Slots per sandbox (node / execution / workflow) |
| `N8N_CODE_SANDBOX_MAX_PER_KEY` | `4` | Sandboxes per scope key in one process |
| `N8N_CODE_SANDBOX_SPARE_WORKERS` | `true` | Each slot keeps a started worker |
| `N8N_CODE_SANDBOX_REUSE_WORKERS` | `false` | One shared worker process runs all tasks of a sandbox, at the same time up to the slot count. Each task has its own scope for the built-ins. The module cache, changes to built-in objects and globals that sloppy code creates are shared while tasks run. A timeout or cancel drops the task, and the process is replaced when no task runs in it. If the process does not respond, the daemon kills it at once and the other running tasks fail |
| `N8N_CODE_SANDBOX_TASK_MEMORY_MB` | `512` | Memory per task |
| `N8N_CODE_SANDBOX_RUNTIME` | `n8n-js` | `n8n-js` (startup snapshot) or `n8n-js-nosnapshot` |
| `N8N_CODE_SANDBOX_TIMINGS` | `true` | Write `code_sandbox_task` and `code_sandbox_lease` records to stdout |
| `N8N_CODE_SANDBOX_TIMINGS_PATH` | — | Also append the records to this file |
| `N8N_SANDBOX_SERVICE_URL`, `N8N_SANDBOX_SERVICE_API_KEY` | — | The sandbox service |

`N8N_RUNNERS_TASK_TIMEOUT` is the task timeout.

The latency, benchmark and load scripts accept `REUSE=true`.
