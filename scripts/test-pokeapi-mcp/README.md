# PokeAPI MCP Server — Test Suite

Vitest-based tests for the **PokeAPI MCP Server** workflow running at
`http://localhost:5678/mcp/pokeapi`.

## Prerequisites

- n8n running locally (`pnpm dev:be`)
- The PokeAPI MCP Server workflow active in your n8n instance
- Dependencies installed (see below)

## Setup

```bash
pnpm install
```

This package is a workspace member, so running `pnpm install` from the repo
root also works.

## Running the tests

```bash
# All tests (LLM evals skipped without API key)
pnpm --filter test-pokeapi-mcp test

# Watch mode during development
pnpm --filter test-pokeapi-mcp test:watch

# Include LLM-driven evals
ANTHROPIC_API_KEY=sk-ant-... pnpm --filter test-pokeapi-mcp test

# Point at a different MCP URL
MCP_URL=http://127.0.0.1:5678/mcp/pokeapi pnpm --filter test-pokeapi-mcp test
```

## Test sections

| # | Section | What it checks |
|---|---|---|
| 1 | **Contract** | `tools/list` shape, every tool's `inputSchema` is valid JSON Schema, response payloads parse against Zod schemas |
| 2 | **List_Pokemon** | Total count, pagination (limit + offset), all generation/region filter variants (number, name, region alias) |
| 3 | **Get_Pokemon** | Lookup by name and numeric ID, generation fields, full evolution chain (basic / middle / final stages, `evolves_from`, `evolves_to`) |
| 4 | **Search_Pokemon** | Each filter in isolation (name, type, ability, evolutionStatus), combined filters, limit enforcement |
| 5 | **Edge cases** | Non-existent Pokémon (`found=false`), out-of-range IDs, offset past end, unknown type/ability, no filters at all |
| 6 | **Latency** | Single-call budget (< 10 s), 3 concurrent GETs, burst of 5 List calls |
| 7 | **LLM evals** | Claude Haiku selects the right tool and parameters for 5 natural-language prompts — skipped when `ANTHROPIC_API_KEY` is not set |
| 8 | **Regression** | Vitest snapshots of known-good full records (bulbasaur, pikachu, charmeleon, gen-1 list) |

## Updating snapshots

Regression snapshots are stored in `__snapshots__/pokeapi-mcp.test.ts.snap`.
Update them after an intentional upstream API change:

```bash
pnpm --filter test-pokeapi-mcp test -- --update-snapshots
```

## File structure

```
scripts/test-pokeapi-mcp/
├── mcp-client.ts          MCP session management (initialize, tools/list, tools/call)
├── pokeapi-mcp.test.ts    All test suites
├── vitest.config.ts       30 s timeout for external API calls
├── package.json
└── __snapshots__/         Auto-generated by Vitest on first run
```
