# Gym differential test: v1 engine and compiled engine

Generated by `node scripts/gym-diff.ts`. The explanations come from `scripts/gym/notes.ts`.

## How to run

```bash
cd packages/@n8n/workflow-lang
node scripts/gym-diff.ts                # build, start, run all, stop, write this report
node scripts/gym-diff.ts --only Slack   # workflows whose path has "Slack"
node scripts/gym-diff.ts --eligibility-only
```

The gym source is `../ai-gym` next to the n8n folder, or `GYM_SRC`. The command builds the gym
(`go build ./cmd/gym`), `wfrt` (`zig build -Drelease=true`) and the fallback host, starts them on
free ports, runs the workflows in a pool (`--concurrency`, default 4; `--timeout`, default 60 s
for each engine), and stops every process by its PID. Each workflow has a folder
`<work>/runs/<n>/` with `run.log`, the bound workflow, the converted source, the events of `wfrt`,
the node outputs and both gym states. `--baseline <work>/summary.json` adds the numbers of an
earlier run as a "before" column.

## Method

- **Eligibility.** `scripts/gym/eligibility.ts` reads the `needed_by` lists of the gym contracts
  (`ai-gym/services/<name>/sim-service.json`, for example `n8n:slack@2.7 message.post`). A node
  that runs (reachable from the trigger, not disabled) is external when it is not a core node.
  Its resource and operation (with the defaults of the node description) must be in the list of
  the service, and its credential type must be one that the gym issues. HTTP Request nodes
  need a literal URL whose host the gym serves.
- **World and credentials.** One tenant per workflow, seeded with the merged example worlds of
  its services (`scripts/gym/world.ts`). API-key credentials come from the tenant document
  (`n8n_credentials`); OAuth2 credentials come from `POST …/credentials`, with a connected
  `oauthTokenData`. Every node with a credential points at the gym credential of its type.
- **Same start state.** After seeding, the script takes a snapshot of the tenant. Run (a) uses
  the tenant; then the script deletes it and restores the snapshot into the same tenant id for
  run (b). Both runs thus start from the same world, with the same native ids and credentials.
  (Two tenants seeded from one world get different random ids and tokens, which would need a
  rewrite of the workflow for each run.)
- **Run (a)** is n8n's `WorkflowExecute` in a child process (`scripts/gym/v1-run.ts`, through
  `oracle-engine.ts`), with the node types of the fallback host (n8n-nodes-base and LangChain)
  and a credentials helper that does what the CLI's helper does (defaults, `$self` expressions,
  `authenticate`, `preAuthentication`). `NODE_OPTIONS=--require=resolve.cjs` and
  `NODE_EXTRA_CA_CERTS` send vendor hosts to the gym.
- **Run (b)** converts the same JSON with `trace: 'all'`, compiles it, loads it into `wfrt`
  through the admin API with the section 7 credentials document (`buildCredentialsFile`, from
  the data that run (a) resolved), and starts a manual execution with trace on. `wfrt` runs
  with `--gym-env` and `--ca-file`; the fallback host with resolve.cjs.
- **Compare.** The output items of every node (all runs, one list for each output) from the
  oracle's run data and from the `trace` events, and `GET …/state` of the tenant after each
  run.

### Normalizations

Only these differences are ignored (`scripts/gym/normalize.ts`):

1. **time**: two instants inside the time window of their own run (5 minutes of slack each side),
   or with the same offset from the start of their run within 5 s (an expiry such as "now + 1 hour"):
   ISO 8601 or RFC 2822 strings, epoch seconds or milliseconds, Slack `ts` values, and ISO times
   at the same places inside a longer text.
2. **id**: two strings with one id format (a UUID; 12 or more hex characters; 6 or more digits; or
   8 or more letters and digits mixed, with the same length and short prefix) that neither the
   workflow JSON nor the seeded tenant snapshot holds (so a run made them), when one map from (a)
   values to (b) values holds over the whole workflow (outputs and state together), both ways.
3. Rules 1 and 2 on the tokens of a string with the same separators (URLs, texts with an id).
4. Positive integers under a key `id` or `…Id` follow rule 2.
5. The hex `signature` of a resume URL: each engine signs with its own secret.
6. When both runs wait for a resume at the same node, the v1 run of that node (its input items)
   is left out: the compiled run traces the node only when it resumes.

Both runs use the same execution id and the same resume URL bases, so `$execution.id` and
resume URLs compare as they are. Binary data compares as the `$binary` key of each item (the
v1 run adds it from the item's `binary`, spec 10).

No key is dropped and item order counts. Trailing empty outputs are dropped, as in
`compare.ts`.

## Runtime and compiler findings (not fixed here)

- **Compiler: hoisted function declarations capture registers, not cells.** `src/compiler` creates the
  closure of a function declaration at the start of `run`, before the `NEWCELL` of a `let` or `const` it
  captures (`wfc disasm`: `CLOSURE` at pc 1, `NEWCELL` at pc 4). `wfrt` then fails with
  `TypeError: value is not a cell`; the reference runner gives the right value, so the convert-coverage
  oracle could not see it. Reproduction: `node scripts/gym/repro/hoisted-closure.ts`. Fixed now in
  `src/compiler/lower.ts` (`hoistFunctions` creates the cells first); `src/__tests__/hoisted-closure.test.ts`
  runs the pattern on the reference runner and checks the cell order in the bytecode. The converter keeps
  arrow functions for node functions.
- **Runtime: no `failed` step event before `needs_attention`.** Spec 9.2 says each effect gets `started`,
  then `completed` or `failed` with the error. A step that fails outside a try block ends with
  `finished`/`needs_attention` and no `failed` event, also with `trace: true`, so n8n cannot show the
  error. Reproduction: `node scripts/gym/repro/needs-attention.ts` (exits 1). The test reads the error by
  running the step again in the host's node runner after it has read the gym state (logs say "step re-run").
- **Runtime: parked `needs_attention` executions keep their module.** In a run that did not cancel them,
  `PUT /_admin/workflows` answered 507 ("no room") from the 525th load on, with 247 executions parked in
  `needs_attention` (each on an unloaded workflow version).
  This is as spec 9.1 says (a parked execution keeps its version), but nothing frees them unless n8n
  cancels them. The test now cancels each such execution (`DELETE /_admin/executions/<id>`).
- **Runtime: `--gym-env` keeps 128 host patterns.** The gym lists 367; `wfrt` keeps the first 128
  (`shell/gym.zig`, `max_patterns`) without a warning. Names after them still resolve through `GYM_DNS`,
  so no run failed because of it.

  - an object field reads JavaScript object literals (`acceptJSObject`);
  - in raw mode, a bare `undefined` becomes null (`repairJSON`).
- Code node: `$itemIndex` is 0 in "all items" mode.
- A manual run of a polling trigger polls in the fallback host, and gives `[{}]` when it finds nothing.
- A whole-node failure under "continue (using error output)" passes the input on output 0 and
  records the error on that run.
- A credential type that the runtime cannot apply (`src/credentials/not-injectable.generated.ts`,
  written by `scripts/credential-coverage.ts`) sends its node to the fallback host.
- `wfrt` and the TS VM: the optional parameters of the string, array, number and `parseInt`
  methods follow V8 (corpus `36-optional-params`, checked by `lib-dts-optional.test.ts`).

Known v1 quirks that the compiled engine does not model:

- **An error object in an item (09808).** n8n 2.42.2 evaluates expressions in an isolate. A node
  that fails and goes on (`continueRegularOutput`) can put its live `NodeApiError` object into
  `json.error`, for example Airtable "search". The expression bridge cannot copy that object.
  So `$input.first()`, `$input.all()`, `$('Node').first()` and `$('Node').all()` throw inside the
  isolate, and the expression is null. Property access such as `$json.error.message` still
  works. The compiled engine keeps items as JSON, so these calls give the items. The bundle is
  left out of the counts.
